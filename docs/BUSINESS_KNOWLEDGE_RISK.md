# 用户研判与风险规则总结

> 来源：`用户研判规则/投资者风险画像研判规则.md`、`用户研判规则/反洗钱可疑交易识别规则.md`、`用户研判规则/用户信息数据示例.md`、`用户研判规则/用户信息数据示例.txt`
> 用途：画像字段、构造数据、行为特征、产品推荐和交易风控。

## 1. 示例客户

现有构造样例包括：

```text
客户A：25岁，年收入15万，稳健型，投资经验2年
客户B：45岁，年收入200万，进取型，投资经验15年
客户C：60岁，年收入10万，保守型，投资经验5年
客户D：35岁，年收入50万，平衡型，投资经验5年
客户E：28岁，年收入30万，激进型，投资经验3年
```

这些数据只能作为 `source_type=synthetic` 的构造数据。

## 2. 画像维度

```text
基础：年龄、性别、职业、学历、婚姻、城市
财务：收入、资产、净资产、负债、月可投资金额
投资：风险等级、经验、偏好产品、目标、期限、交易风格
行为：活跃度、咨询频率、产品关注、信息来源、追热点倾向
生命周期：人生阶段、近期/中期/远期目标、特殊需求
```

## 3. 主观/客观分层

### 主观

```text
用户自述目标
可接受亏损
期望收益
投资期限
流动性需求
产品偏好
```

### 客观

```text
系统验证资产
真实持仓
交易记录
风险问卷分数
平均持仓天数
实际风险暴露
```

### 推导

```text
画像一致性
风险暴露
流动性压力
产品推荐置信度
主观与客观冲突
```

## 4. 风险等级

普通投资者五档：

```text
C1 保守型
C2 稳健型
C3 平衡型
C4 进取型
C5 激进型
```

产品风险五档：

```text
R1 低风险
R2 中低风险
R3 中风险
R4 中高风险
R5 高风险
```

基础匹配：

```text
C1 → R1
C2 → R1-R2
C3 → R1-R3
C4 → R1-R4
C5 → R1-R5
```

风险不匹配时应拒绝或进入明确的二次确认流程，不能由 Agent 自行放行。

## 5. 画像一致性

需要比较：

```text
用户声明长期投资 vs 实际平均持仓周期
用户声明低风险 vs 实际高风险持仓
用户申报收入 vs 实际交易金额
用户声明不需要流动性 vs 高频赎回
```

输出：

```text
consistent
conflict
insufficient_data
```

## 6. AML 可疑交易规则

规则示例：

```text
RW-001：单日大额现金交易
RW-002：7日频繁小额交易
RW-003：24小时内资金快进快出
RW-004：多来源分散转入、集中转出
RW-005：集中转入、分散转出
RW-006：交易金额与客户身份不符
```

规则输出应包含：

```text
rule_code
risk_level
triggered_at
customer_id
evidence
response_deadline
case_status
assigned_staff
```

## 7. 风险预警流程

```text
交易/行为事件
→ 规则计算
→ 生成 RiskAlert
→ 分配风控/AML 人员
→ 人工调查
→ 关闭、升级或上报
→ 审计留痕
```

实时、准实时、日批和周期规则需要区分调度方式；当前项目可以先做同步规则模拟。
