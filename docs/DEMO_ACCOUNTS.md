## 一、角色范围

账号业务角色以需求文档为准，仅保留以下角色：

| 账号类别 | 角色 | 说明 |
|---|---|---|
| 内部员工 | 理财顾问 | 客户画像分析、产品推荐、申购/赎回/风评和产品查询 |
| 内部员工 | 风控专员 | 交易监测、风险规则、预警和可疑交易上报 |
| 内部员工 | 客户经理 | 客户资料维护、订单处理、转账和工单 |
| 内部员工 | 审计 | 全量业务数据只读和审计日志查询 |
| 外部客户 | 零售投资者 | 个人客户自助咨询、风险测评、交易、资产和订单查询 |
| 外部客户 | 高净值客户 | 高净值客户自助服务，权限边界与零售投资者一致，数据层级不同 |

`super_admin` 仅作为系统维护标记，不是业务账号角色；开发环境的系统维护账号使用“审计”业务角色承载，只额外拥有系统管理权限。`employee_pending` 仅用于新员工注册后的待分配状态，不属于可选业务角色。

## 三、权限矩阵

权限只描述后端资源边界；客户账号只能访问自己的资产、订单和画像，不能因为拥有产品读取权限而访问员工端知识图谱或客户数据。

| 权限码 | 理财顾问 | 风控专员 | 客户经理 | 审计 | 零售投资者 / 高净值客户 |
|---|:---:|:---:|:---:|:---:|:---:|
| `customer:read` 查看客户资料 | ✓ | ✓ | ✓ | ✓ | — |
| `customer:write` 管理客户资料 | — | — | ✓ | — | — |
| `product:read` 查看产品信息 | ✓ | ✓ | ✓ | ✓ | ✓ |
| `product:write` 管理产品/知识 | — | — | — | — | — |
| `risk:read` 查看风险信息 | ✓ | ✓ | — | ✓ | — |
| `risk:write` 管理风险规则 | — | ✓ | — | — | — |
| `asset:read` 查看资产 | ✓ | — | ✓ | ✓ | ✓（仅本人） |
| `order:read` 查看订单 | ✓ | ✓ | ✓ | ✓ | ✓（仅本人） |
| `order:write` 审核/处理订单 | — | — | ✓ | — | — |
| `audit:read` 查看审计日志 | — | — | — | ✓ | — |
| `admin:write` 系统管理 | — | — | — | — | — |

系统维护标记拥有全部权限，但不作为普通业务角色出现在角色选择列表中。

说明：客户账号的 `product:read` 仅用于浏览可售产品和获取客服返回的产品信息，不授予知识图谱统计、客户图谱可视化或产品-行业关联接口访问权限。

说明：`risk:read` 仅用于客户风险信息和适当性查询；“风控预警”和风险工单属于处置工作台，仅向拥有 `risk:write` 的风控专员及系统维护账号开放。

## 四、业务操作 Agent 权限

| 操作 | 允许角色 |
|---|---|
| 申购、赎回、风评重做、产品详细查询 | 理财顾问 |
| 信息更新、转账、工单创建 | 客户经理 |
| 可疑交易上报 | 风控专员 |
| 全部上述操作 | 系统维护标记（仅开发/运维使用） |

外部客户可以通过客户端的自助交易接口完成本人业务，但不显示员工端的业务操作 Agent、客户管理、风控管理、知识库管理、知识图谱和审计查询功能。客服对话画像抽取也只能由具备 `customer:read` 的内部员工执行。

## 五、演示建议

### 场景 1：零售投资者客户闭环

- 登录 `retail_investor_demo`
- 查看资产与持仓、完成风险测评、浏览产品、创建并确认订单
- 使用智能客服咨询产品；客户端不显示员工画像抽取和员工业务操作功能

### 场景 2：高净值客户投顾数据

- 登录 `high_net_worth_demo`
- 查看高净值客户资产、画像增强和智能客服
- 客户端不展示知识图谱；图谱仅供内部投顾、业务分析和 GraphRAG 工作流使用

### 场景 3：内部员工分工

- `financial_advisor_demo`：客户画像、产品推荐和投顾操作
- `risk_specialist_demo`：风控预警和可疑交易上报
- `customer_manager_demo`：客户资料、订单审核和业务工单
- `auditor_demo`：只读业务数据和审计日志

### 场景 4：系统管理

- 登录 `super_admin_demo`
- 管理用户、业务角色权限和回收站数据
- 该账号的业务角色仍显示为“审计”，系统管理能力来自独立的 `is_super_admin` 标记

## 六、说明

- 账号由 `app/services/auth_seed.py` 和 `app/services/demo_customer_seed.py` 在开发环境启动时自动创建或同步。
- 30 位 Mock 客户 + 2 位企业 Mock 客户由 `scripts/seed_rich_data.py` 生成（中等规模演示数据：37 客户画像 / 31 产品 / 200 持仓 / 446 交易），覆盖 C1-C5 全风险等级与普通→私行全层级；密码统一 `Demo@2026Customer`。
- 旧版 `customer`、客服、产品经理、运营、旧风控账号及企业客户演示账号会被软删除，不会再作为可登录账号或角色选项出现。
- 密码中的 `@` 直接输入即可；生产环境不会启用这些演示账号。
- 如需修改密码，请同步修改 `app/services/auth_seed.py` 和相关测试账号配置；不要将真实密码提交到仓库。
