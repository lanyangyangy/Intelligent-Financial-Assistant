# 金融政策与合规知识总结

> 来源：`金融政策/反洗钱合规操作手册.md`、`金融政策/个人投资者适当性管理指南.md`、`金融政策/理财产品销售管理办法.md`
> 用途：KYC、适当性、销售流程、风控校验、审计和 Agent 合规提示。

## 1. KYC 与 AML

核心要求：

```text
开户身份核实
持续身份识别
触发条件重新识别
受益所有人识别
客户风险分类
大额交易报告
可疑交易识别
资料和交易记录保存
内部监控与问责
```

重新识别期间可以限制非柜面业务和大额交易。

## 2. 客户风险

客户风险等级应综合：

```text
身份和职业
收入与资产
投资经验
投资目标
风险承受能力
流动性需求
交易行为
产品持仓风险
```

主观陈述、问卷结果、系统观察和资产事实必须分开保存。

## 3. 适当性管理

核心原则：

```text
将适当的产品销售给适当的投资者
```

关键流程：

```text
投资者分类
→ 风险测评
→ 产品风险评级
→ 硬匹配
→ 风险揭示
→ 双录/确认
→ 冷静期（如适用）
→ 定期复评
```

硬匹配、豁免和拒绝规则必须结构化版本管理。

## 4. 销售行为

销售人员和机构需要满足相应资质；销售过程中需要：

```text
真实、准确、完整披露
不得承诺保本保收益
不得误导销售
不得代客操作
记录风险揭示和确认
保存双录和销售档案
```

## 5. 双录与冷静期

部分高风险产品、特定客户年龄或销售场景需要双录。冷静期内应保留客户撤回/确认等制度化处理。具体是否适用由产品、客户和政策版本共同决定。

## 6. 复评

客户风险评估不是永久有效，应按规则定期复评，并在重大信息变化、资产变化、风险事件或客户主动变更时重新评估。

## 7. 投诉与档案

需要记录：

```text
投诉渠道
投诉分类
处理时限
解决方案
客户反馈
相关销售档案
```

客户身份资料、交易记录、双录和操作日志需要按合规要求保存，具体期限以当前有效制度版本为准。

## 8. 系统实现原则

- 合规硬规则由后端规则服务执行；
- Agent 只能解释和提示，不能替代审批；
- 所有规则需要版本、来源、生效时间和失效时间；
- 关键动作保留审计日志；
- 高风险交易需要人工审核或二次确认；
- 脱敏构造数据必须明确标记 synthetic。
