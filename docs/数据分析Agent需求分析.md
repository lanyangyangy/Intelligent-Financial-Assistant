# 数据分析 Agent 需求分析

## 1. 总体定位（§2.2 五大Agent职责说明）

| 维度 | 定义 |
|---|---|
| **服务对象** | 内部员工（区别于客服/投顾面向客户与顾问） |
| **核心能力** | 自然语言查业务数据 → 生成 SQL → 结果解读 |
| **关键技术** | NL2SQL、Schema 注入、安全校验 |
| **典型场景** | "上季度理财产品总收益率多少？" |

### 1.1 架构位置

- Agent 编排层的 5 类 Agent 之一（架构图中为 `C4`）
- 底层挂接 **NL2SQL Engine**（`D3`）
- 对外暴露工具 **NL2SQL**（§6.4.3），供统一执行骨架调用

### 1.2 与业务操作 Agent（NL2API）的区别

| 对比项 | 数据分析 Agent（NL2SQL） | 业务操作 Agent（NL2API） |
|---|---|---|
| 服务对象 | 内部员工 | 客户经理 |
| 能力 | 只读查询业务数据 | 执行业务操作（申购/赎回/转账等） |
| 安全性 | 仅允许 SELECT | 权限校验 + 二次确认 |
| 例子 | "上季度理财产品总收益率多少？" | "帮客户张三申购10万元XX产品" |

## 2. 功能需求（§Phase 2 / F2.3 数据分析Agent）

### 2.1 对话接口

**`POST /api/chat/analyst`**

- 请求体：`{ session_id, message, user_id }`
- 响应体：`{ reply, sql, query_result, session_id }`

另有统一入口 `POST /api/chat`，通过 `agent_type: "analyst"` 路由到本 Agent。

### 2.2 SQL 生成模块

- 将 **10 张表的 CREATE TABLE 语句（含 COMMENT）** 作为 System Prompt 注入 LLM
- 提供 **3–5 个 few-shot 示例**（自然语言 → SQL 对照）
- LLM 只生成 **SELECT** 语句

### 2.3 安全校验

- 正则检查：禁止 `DROP` / `DELETE` / `UPDATE` / `INSERT` / `ALTER` / `TRUNCATE` 等危险操作
- **仅允许 SELECT 查询**
- 查询结果行数限制：**最多 100 行**
- 拒绝时返回："不允许执行该操作"

### 2.4 SQL 执行与结果格式化

- 执行安全 SQL → 返回结果集
- 结果格式化为表格 / 列表形式

### 2.5 结果解读

- 查询结果 + 原始问题 → LLM 生成自然语言描述
- 示例："上季度理财产品总收益率为 4.32%，较去年同期上升 0.5 个百分点"

### 2.6 支持场景（文档明确列出 4 类）

| 场景 | 示例问题 |
|---|---|
| 持仓查询 | "客户张三目前持有哪些产品？" |
| 收益统计 | "上季度各产品类型的平均收益率是多少？" |
| 交易记录 | "客户A最近一个月的交易记录" |
| 客户统计 | "AUM超过100万的客户有多少个？" |

## 3. 用户故事

- 作为内部员工，我问"上季度理财产品总收益率多少"，系统生成 SQL 查询并返回结果
- 作为内部员工，我问"AUM超过100万的客户有多少个"，系统正确统计并用自然语言描述结果

---

## 4. 验收标准

- ✅ NL2SQL 能正确生成 SELECT 查询并返回结果（测试 **5 个以上**查询场景，准确率 **≥ 80%**）
- ✅ NL2SQL 安全校验生效（拒绝 DROP/DELETE 等危险操作，返回"不允许执行该操作"）
- ✅ 查询结果有自然语言解读（不只是返回表格，还有文字描述）

## 5. 其他相关约束

### 5.1 Tool 规范（§6.4.3）

| 项目 | 说明 |
|---|---|
| 入参 | `query`(str)：自然语言查询；`customer_id`(str)：客户ID；`context`(dict)：上下文 |
| 出参 | `sql_statement`(str)：生成的SQL；`query_result`(list)：查询结果；`interpretation`(str)：结果解读 |
| 说明 | 将自然语言转为 SQL 并执行，返回结果和解读 |

### 5.2 对话落库（审计与回溯）

- 所有 Agent 的对话按轮次写入 `conversation_archive` 表（`agent_type` = 客服/投顾/风控/**数据分析**/业务操作）
- `tool_calls` 记录 LLM 的每一次 NL2SQL / NL2API / GraphRAG 调用

### 5.3 交付物（§7.1 里程碑）

- **Phase 2（P2）**：NL2SQL 数据分析 Agent —— 可将自然语言转为 SQL 查询并返回结果

## 6. 与当前项目实现的对照

工作区实现：`app/agents/analytics_agent.py`（`DataAnalystAgent`），采用 **Generate → Validate → Execute → Interpret** 流程。

| 文档要求 | 当前实现 | 状态 |
|---|---|---|
| 10 张表 CREATE TABLE 注入 | 按意图**动态注入**实际 PostgreSQL 表结构和语义说明，prompt 更精简 | ✅ 合理优化 |
| 3–5 个 few-shot 示例 | 按当前意图注入可执行 SQL 示例，最多 3 个 | ✅ |
| 仅 SELECT + 危险词正则 + 100 行限制 | 单条 SELECT、危险操作、`SELECT INTO`/锁定查询校验，并将显式 LIMIT 封顶为 100 | ✅ |
| 4 类支持场景 | 扩展为 6 个意图：持仓查询/收益统计/交易记录/客户统计/产品统计/工单查询 | ✅ |
| 拒绝返回"不允许执行该操作" | 完全一致 | ✅ |
| 自然语言结果解读 | `_interpret`，空结果 / LLM 失败有降级文案 | ✅ |
| 响应体含 sql / query_result / reply | 专用 `/api/v1/chat/analyst` 返回 `reply`、`sql`、`query_result`、`interpretation`、`session_id` | ✅ |
| 服务对象为内部员工 | `analytics:read` + staff 角色校验，客户账号返回 403 | ✅ |
| NL2SQL 缓存 10 分钟 | Redis 缓存，Redis 不可用时降级进程内缓存，TTL 600 秒 | ✅ |

## 7. 结论

按需求文档，数据分析 Agent 的核心职责是：**面向内部员工，用自然语言查询业务数据** —— 生成只读 SQL（NL2SQL）、安全校验后执行、以"表格 + 自然语言解读"返回结果。该功能属于 **Phase 2（P2 优先级）** 交付物，与客户画像系统、风险评估模块同周期开发。

当前本地验收已覆盖截图中的 6 类场景，均能返回结构化结果或明确的无数据提示；客户账号调用专用接口返回 403，员工账号可正常查询，重复问题可命中 600 秒缓存。
